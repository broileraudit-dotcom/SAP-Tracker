# متابعة أوامر إنتاج Broiler

تطبيق ويب (Supabase + GitHub Pages) لمتابعة أوامر الإنتاج: 29 يوماً لكل أمر، ولكل يوم مهمتان (تأكيد إنتاجية + تسجيل فحوصات)، مع حساب التأخير.

## التشغيل
1. **Supabase**: أنشئ مشروعاً ← SQL Editor ← شغّل `supabase/schema.sql` ثم `supabase/seed.sql` (أوامر ملفك: 202 أمر).
2. **المستخدمون**: Authentication ← Users ← Add user (بريد + كلمة مرور). عطّل التسجيل الذاتي من Sign In / Providers.
3. **GitHub**: ارفع المجلد كمستودع. Settings ← Pages ← Source: *GitHub Actions*.
   Settings ← Secrets and variables ← Actions: أضف `SUPABASE_URL` و`SUPABASE_ANON_KEY` (من Project Settings ← API).
4. أي push على `main` ينشر الموقع تلقائياً.

للتجربة محلياً: عدّل `web/config.js` وافتح `web/index.html`.

## كيف يعمل
- **أمر جديد** ← يُنشئ 29 يوماً تلقائياً (اليوم n = تاريخ البدء + n، نهاية الأمر = البدء + 29). حذف/إضافة يوم من نافذة الأمر وتتحدّث نهايته تلقائياً.
- **حالات الأمر**: مفتوح ← تم بدء العمل ← جار العمل ← مراجعة نهائية وإغلاق فني ← مغلق نهائياً.
- **المهام المطلوبة**: كل مهمة استحقت (اليوم أو قبله) ولم تُنفذ في أمر غير مغلق، مرتبة بالأكثر تأخراً، وزر «تم التنفيذ».
- **التأخير** = تاريخ التنفيذ − تاريخ الاستحقاق (أو اليوم − الاستحقاق للمعلّق). التوقيت Asia/Riyadh.
- **افتراض في البيانات الأولية**: الأوامر في «مراجعة نهائية/مغلق» تُعتبر مهامها منفذة في موعدها؛ غيّر ذلك في آخر `seed.sql` إن لزم.
- ورقة Prepared House لم تُستورد (بلا تواريخ)؛ أي أمر مادته غير Broiler يُنشأ بلا أيام.
- تحديث البيانات من إكسل: `python tools/make_seed.py ملفك.xlsx > supabase/seed.sql`.
